# 메뉴 막대 모아보기

macOS 메뉴 막대 오른쪽의 앱·시스템 항목을 별도의 일반 앱 창에서 찾아 메뉴를 열 수 있게 하는 앱입니다. 이 앱 자체는 메뉴 막대 아이콘을 만들지 않습니다.

- 손쉬운 사용(Accessibility) API가 알려 준 항목만 표시합니다. **"발견한 항목"** 이며 숨겨진 항목 전체나 모든 노치 뒤 항목의 지원을 보장하지 않습니다.
- 로컬 개발 단계입니다. 배포용 서명·공증·DMG·다운로드 링크는 없습니다.
- 검증 범위와 한계: [docs/technical-validation.md](docs/technical-validation.md)

## 기능

- 접근 가능한 메뉴 막대 항목 목록(앱 아이콘, 항목 이름, 앱 이름), 검색(앱 또는 항목 이름), 새로고침(⌘R, 앱 활성화 시 자동 갱신)
- 선택한 행은 둥근 선택 면과 강조색 선으로 표시되고, 그 행의 "메뉴 열기"만 강조됩니다. 다른 행의 "메뉴 열기"는 조용한 글자로 두며, 마우스를 올린 행은 테두리 버튼으로 바뀝니다. 선택한 행에서 Return 키로 메뉴 열기를 요청할 수 있습니다.
- "메뉴 열기": 지원 액션(AXPress 등)을 항목에 1회 요청합니다. 메뉴는 원래 메뉴 막대 위치에서 열립니다.
- 노치 영역과 좌표가 겹치는 항목은 앱 이름 옆에 작은 표시가 붙습니다(표시용이며 항목을 걸러내지 않음).
- "앱 열기", "앱 종료…": 행의 ⋯ 메뉴(접근성 이름 "<앱 이름> 앱 작업")나 우클릭 메뉴에 있습니다. 소유 앱이 `/System` 밖의 최상위 `.app`으로 확실할 때만 나타납니다. 종료는 확인 창(앱 이름·PID)을 거친 정상 종료 요청(`terminate`)만 보내며 강제 종료하지 않습니다. 저장 확인은 대상 앱이 처리합니다.
- 응답이 없거나 결과를 확인하지 못해도 같은 요청을 자동으로 다시 보내지 않습니다. 행에 결과를 표시하고 새로고침 전까지 그 항목의 메뉴 열기를 막습니다.
- 하단에는 발견한 항목 수와 조회한 앱 수를 표시합니다. 조회 실패는 같은 앱·같은 원인끼리 개수로 묶어 요약하고, **자세히**에서 전체 목록을 볼 수 있습니다(실패를 숨기지 않음).
- 권한 안내 화면은 "1. 시스템 설정에서 켜기(권한 요청, 시스템 설정 열기) → 2. 돌아와서 권한 다시 확인(확인 시각과 결과 표시)" 순서이고, 아래 복구 패널에 재등록 방법, 현재 실행 중인 앱 경로, **이 앱 위치 열기**가 있습니다.
- 창은 기본 900×640, 최소 560×420이며 시스템의 밝은·어두운 모드를 따릅니다(navy & slate 테마).
- 화면 녹화, 서버, 계정, 외부 전송은 없습니다.

## 지원 환경

- macOS 14.0 이상(`LSMinimumSystemVersion`). 실제로 확인한 환경은 macOS 26.3 하나입니다.
- 빌드한 컴퓨터의 CPU 아키텍처용으로만 만들어집니다(Apple 실리콘에서 빌드하면 arm64).
- 노치가 없는 Mac이나 외장 모니터에서도 실행되지만 해당 조건은 검증하지 않았습니다.

## 필요한 개발 도구

- Xcode(Swift 5.9 이상 도구 체인). 개발에는 Xcode 26.6 / Swift 6.3.3을 사용했습니다.
- 외부 패키지 의존성은 없습니다.

## 빌드

```bash
scripts/build-app.sh      # build/MenuBarGather.app 생성 (ad-hoc 서명)
swift test                # 핵심 로직 자동 검증(9개)
```

Swift 모듈 캐시가 `~/.cache`에 쓰지 못하는 환경이면 `CLANG_MODULE_CACHE_PATH=$PWD/.build/modcache`를 지정하세요(스크립트에는 이미 들어 있습니다).

## 설치

설치는 직접 복사합니다(스크립트가 자동으로 설치하지 않습니다).

1. 위 빌드 명령으로 `build/MenuBarGather.app`을 만듭니다.
2. Finder에서 `build/MenuBarGather.app`을 `/Applications`(응용 프로그램) 폴더로 끌어다 놓거나 복사합니다.
3. 응용 프로그램 폴더, Launchpad 또는 Spotlight에서 "메뉴 막대 모아보기"를 실행합니다. 실행 중에는 Dock에 나타나며, 창을 닫은 뒤 Dock 아이콘을 누르면 창이 다시 열립니다.

설치하지 않고 `open build/MenuBarGather.app`으로 바로 실행해도 됩니다.

## 손쉬운 사용 권한 설정

앱을 처음 실행하면 권한 안내 화면이 나옵니다. 앱은 권한 설정을 자동으로 바꾸지 않습니다.

1. 안내 화면의 **권한 요청**을 누르거나 **시스템 설정 열기**를 누릅니다.
2. 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용에서 "메뉴 막대 모아보기"를 켭니다. 목록에 없으면 `+` 버튼으로 현재 실행 중인 앱을 추가합니다.
3. 앱으로 돌아와 **권한 다시 확인**을 누릅니다. 앱이 활성화될 때도 자동으로 확인합니다. 아직 허용되지 않았다면 확인 시각과 함께 그렇게 표시됩니다. 켜져 있는데도 허용되지 않으면 아래 "설정에서 켜져 있는데도 허용되지 않을 때"를 따르세요.

실행 중에 권한이 해제되면 조회와 실행을 멈추고 안내 화면으로 돌아갑니다.

### 설정에서 켜져 있는데도 허용되지 않을 때

이 앱은 ad-hoc 서명이라서 코드가 달라지는 재빌드나 앱 교체 때 서명 해시(cdhash)가 바뀝니다. 시스템에 남은 이전 허용 기록과 현재 앱이 맞지 않으면, 설정 화면의 토글이 켜져 있어도 macOS는 이 앱을 허용하지 않을 수 있습니다. 이 경우 토글을 껐다 켜거나 앱을 다시 실행하는 것만으로는 해결되지 않습니다. 권한 안내 화면에는 "macOS가 아직 이 앱을 허용하지 않았습니다"와 확인 시각이 표시됩니다.

1. 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용 목록에서 "메뉴 막대 모아보기"(또는 MenuBarGather) 항목을 선택하고 `−` 버튼으로 제거합니다.
2. 권한 안내 화면의 **이 앱 위치 열기**를 눌러 Finder에서 현재 실행 중인 앱(경로는 화면에 표시됩니다)을 선택하고, 목록의 `+` 버튼으로 그 앱을 다시 추가한 뒤 켭니다. 같은 이름의 앱이 `build/`와 `/Applications`에 함께 있다면 실제로 실행 중인 쪽을 추가하세요.
3. **권한 다시 확인**을 누릅니다. 반영되지 않으면 앱을 다시 실행하세요.

앱을 다시 빌드할 때마다 위 확인이 필요할 수 있습니다. 앱은 허용 상태를 강제로 바꾸거나 권한을 초기화하지 않습니다.

## 검증용 도구

- `.build/debug/menubar-dump`: 조회 결과 출력(읽기 전용). `--press <pid:index>`는 지정한 항목에 메뉴 열기를 1회 요청합니다. 터미널에 손쉬운 사용 권한이 필요합니다.
- `scripts/build-fixture.sh` → `build/MenuBarFixture.app`: 시험용 상태 항목 앱(앱 종료 검증 등). 직접 만든 시험 대상에만 사용하세요. 다른 앱을 무작위로 누르거나 종료하지 마세요.

## 구조

- `Sources/MenuBarKit`: 항목 모델, 이름·검색·소유 앱 판정, 조회 실패 묶음, 접근성 조회·실행(`AXScanner`)
- `Sources/MenuBarGather`: SwiftUI/AppKit 앱(창, 권한 안내, 목록, navy & slate 테마)
- `Sources/menubar-dump`, `Sources/menubar-fixture`: 검증용 CLI·시험 항목
- `Tests/MenuBarKitTests`: 핵심 로직 테스트
- `docs/`: 기획서, 기술 검증, 계획, 작업 기록
