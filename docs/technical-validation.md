### 메뉴 열기 결과(시험 항목, 각각 새로 띄운 프로세스에서 1회)

| 대상 | 노치 영역과 겹침 | 호출 결과 | 메뉴 창이 실제로 나타났는가 |
| --- | --- | --- | --- |
| F0 (x 780–818) | 겹침 | 2.01초 후 응답 없음 | 나타남 (layer 101, x 777, y 40) |
| F1 (x 746–782) | 겹치지 않음 | 0.32초, 성공 | 나타남 (x 743, y 40) |
| F1을 앱 버튼으로(앱이 전면) | 겹치지 않음 | 오류 -25205 | 나타남 |

해석(관찰한 범위에서만):
- **AXPress의 반환값은 메뉴가 열렸는지를 알려 주지 못한다.** 타임아웃이나 -25205에서도 메뉴가 열렸다. 그래서 앱은 이런 결과를 "실행됐을 수 있음(결과 미확인)"으로 표시하고 자동 재시도하지 않는다.
- 노치에 걸친 시험 항목에서도 메뉴는 메뉴 막대 아래(y 40)에 열려 보이는 위치에 나타났다.
- 메뉴 창 확인은 `CGWindowList`로 한 것이며 화면 캡처로 눈으로 확인한 것은 아니다.

## 구현에 반영한 시간 제한

AX 타임아웃은 요소별로 설정되며 자식 요소에 상속되지 않는다. 그래서 요소마다 설정하고, 시스템 전체 타임아웃도 설정했다. 앱 하나의 조회에는 3초 예산을 두며, 첫 "응답 없음"이 관찰되면 그 앱의 추가 조회를 멈추고 부분 실패로 보고한다. 조회 중 권한 해제가 관찰되면 결과를 반영하지 않고 권한 안내 화면으로 전환한다.

## 노치 안쪽 실제 항목 1건 확인 (Tailscale)

감독 지시에 따라 조회에서 발견된 Tailscale 항목 하나에만, 메뉴를 여는 `AXPress`를 정확히 1회 요청했다(22:57).

- 대상: pid 3345 `Tailscale`, 항목 `3345:0`(이름 없음, 지원 액션은 `AXPress`뿐). 직접 토글 액션이라는 근거는 없었다.
- 직전 조회 좌표: x 885–909, y 7–31. 노치 영역(x 790–1010, y 0–38) 안에 **완전히 포함**됨(`notch=true`).
- 호출 결과: 2.01초 후 `noResponse`(타임아웃). 반환 코드는 성공이 아니다.
- 메뉴 창 관찰: 요청 1.0초 뒤에는 Tailscale의 메뉴 창이 없었고, 3.2초 뒤 `CGWindowList`에 layer 101 창(x 874–1265, y 40–317)이 나타났다. 노치 영역 아래쪽(y ≥ 40)이라 노치에 가리지 않는 위치다. 몇 초 뒤에는 창이 없어져 있었다.
- 한계: 메뉴가 화면에 보이는 모습은 **눈으로 확인하지 못했다.** 스크린샷은 메뉴가 나타나기 전(1.0초)과 사라진 뒤에만 찍혔다. 메뉴 창이 생긴 시점과 사라진 시점은 호출 반환과 어떻게 대응하는지 알 수 없다.
- 안전: 메뉴 안의 항목은 누르지 않았고, Escape 등 키 입력도 보내지 않았다. Tailscale 연결·설정·실행 상태는 바꾸지 않았다(검증 후에도 프로세스 실행 중).
- 결론: 노치 안쪽 항목에서도 메뉴 창이 열린다는 증거가 하나 생겼다. 다만 표본이 1건(메뉴 방식)이고 시각 확인이 없어서 "노치 뒤 항목을 사용할 수 있다"로 일반화하지 않는다.

## 미검증

- 노치 안쪽 항목의 메뉴를 사람이 눈으로 확인하고 조작하는 흐름. Tailscale 이외의 안쪽 항목, 팝오버 방식 항목.
- 노치 없는 외장 모니터, 메뉴 막대 자동 숨김, 다중 모니터.
- 팝오버 방식 상태 항목(시험 항목은 NSMenu 방식만 만들었다).
- 앱 자체에 손쉬운 사용 권한을 허용한 상태의 실행과 권한 회복·실행 중 해제 흐름(조회 중 해제 처리는 코드로만 확인).
- 종료 요청 후 대상 앱이 저장 확인 등으로 종료하지 않는 경우(`stillRunning`)와 요청을 받지 않는 경우의 화면(함수 수준 테스트만).
- VoiceOver·키보드 전체 흐름. 목록·종료 화면의 시각 확인(스크린샷 없음).
- Dock 아이콘을 직접 눌러 창을 다시 여는 동작(`open`으로 같은 앱을 다시 실행해 확인했다).
- macOS 26.3 이외의 OS.

## 감독 검수 메모

감독 세션이 `build/MenuBarGather.app`의 권한 안내 창 스크린샷으로 navy/slate 렌더링을 확인했고, "권한 요청 / 설정 열기 / 다시 확인" 버튼이 접근성 요소로 노출됨을 확인했다(당시 앱에 손쉬운 사용 권한 없음). 종료 확인 창의 앱 이름·PID·취소/종료 요청 버튼도 감독의 접근성 상태에서 확인했다. 감독은 수정 반영 후 `swift test` 7개 통과, 서명·plist·셸 구문 검사를 다시 확인했다. 목록 화면은 감독이 직접 보지 못했다. 앱 자체의 손쉬운 사용 권한은 사용자에게 허용을 요청한 상태이며, 허용 후의 실행 확인은 아직 기록하지 않았다.
